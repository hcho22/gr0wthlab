# src

The Marketing Engineer's code.
It changes only through firstmate's reviewed pull requests (Guardrail G8) and is outside the agent's writable tree.
US-ME02 chose Codex as the runtime and Python 3.9 or newer, standard library only, as the language; the launcher runs under the Mac's `/usr/bin/python3`.
Why, and the boundary the launcher enforces: [the US-ME02 spike note](../docs/spikes/us-me02-runtime-boundary.md).

- [`bin/gr0wthlab`](bin/gr0wthlab): the launcher, the one entry point for scheduled and on-demand runs (`run`, `show-config`, `preflight`, `check-incoming`, `check-drafts`, `check-edits`, `rebuild-asset`, `check-beta-drafts`, `check-work`, `launch-agent`, `boundary-check`), and for the Founder's sitting (`sitting`).
- [`gr0wthlab/`](gr0wthlab/): the launcher's package; [`cycle.py`](gr0wthlab/cycle.py) is one run from start to saved records, [`launcher.py`](gr0wthlab/launcher.py) starts the agent inside the boundary, [`process.py`](gr0wthlab/process.py) is where every process the launcher waits for starts, each with a time limit, and [`attempts.py`](gr0wthlab/attempts.py) tells from the launcher's records whether the week's run is still owed, which every start of the weekly schedule checks first.
- [`gr0wthlab/founder.py`](gr0wthlab/founder.py): the Founder's records in `ledger/founder/`, and the one place that states and enforces who may write them and what is ever read as one.
  [`sitting.py`](gr0wthlab/sitting.py) is the Founder-side command's logic and the only code that writes a record, [`page.py`](gr0wthlab/page.py) draws its views with everything shown as text, and [`serve.py`](gr0wthlab/serve.py) serves them on the loopback address behind a secret; [`sitting/`](sitting/) holds the page's own style sheet, script, and icon.
- [`instructions/`](instructions/): the fixed parts of each session's task definition, in [`weekly-run/`](instructions/weekly-run/), which only a reviewed pull request changes; the agent's refinable guidance lives in `workspace/instructions/`.
  [`gr0wthlab/sessions.py`](gr0wthlab/sessions.py) fixes the order of a run's sessions, one for each workflow with work due, and puts each session's task definition together from those parts.
- [`gr0wthlab/posts.py`](gr0wthlab/posts.py): the post-Draft workflow (US-ME08): which calendar days a run prepares, and which Drafts become post items; the checks themselves are in `drafts.py`, `kit.py`, `lint.py`, and `codebase.py`.
- [`gr0wthlab/filming.py`](gr0wthlab/filming.py): the filming workflow (US-ME09): the filming plan as one Review Queue item, the footage place only ever read, and each edit record turned into a finished video; the shot lists are read from the kit in `shots.py`, the edit-record checks are in `edits.py`, the footage listing in `footage.py`, and `ffmpeg` and `ffprobe` are driven from `video.py`.
- [`gr0wthlab/beta.py`](gr0wthlab/beta.py): Beta Cohort recruiting (US-ME15): the Founder's gate, the next invitation batch by entry identifier, the counts the Founder reports, and which recruiting Drafts become message items; the Draft's checks are in `beta_drafts.py`, and the order invitations go out in is in `waitlist.py`, the view's one reader.
- [`gr0wthlab/fetch.py`](gr0wthlab/fetch.py): the launcher's only way onto the network besides a run in the production clone reaching GitHub (`records.py`, `visibility.py`): a credential-free GET to a host listed in `config/guardrails/fetch.json`, bound by that host's `robots.txt`; the sandboxed agent has no network.
  [`sources.py`](gr0wthlab/sources.py) reads the fixed list in `config/sources.json` into one dated snapshot, which is working data removed when the run ends.
- [`gr0wthlab/results.py`](gr0wthlab/results.py): the results a Weekly Read judges (US-ME11): which read is due, exactly what it asks the Founder to give on the sitting page, and each post's numbers taken in as Evidence; [`weekly_read.py`](gr0wthlab/weekly_read.py) is the Weekly Read itself (US-ME12): the launcher's checks of the agent's memo, the memo the Founder reads, and one decision item for each of its lines.
- [`gr0wthlab/listening.py`](gr0wthlab/listening.py): the Listening workflow (US-ME13); [`evidence.py`](gr0wthlab/evidence.py) decides which quote records are kept and counts confidence.
- [`gr0wthlab/outreach.py`](gr0wthlab/outreach.py): the outreach workflow (US-ME14); [`messages.py`](gr0wthlab/messages.py) holds every check of a message Draft, replies included.
- [`gr0wthlab/learning.py`](gr0wthlab/learning.py): the rejection-reason codes and their split (F4), and the guard that puts the agent's Instructions back after every session of a run.
- [`dispatches/`](dispatches/): Dispatch requests in the Review Queue item format, which the launcher files for the Founder's approval, each once ([`dispatch.py`](gr0wthlab/dispatch.py)); the first is RepToday's Waitlist, whose anonymous view [`waitlist.py`](gr0wthlab/waitlist.py) reads.
- [`proposals/`](proposals/): package-change proposals the launcher files once each, such as the brand lint's word lists and the wording that says the floor counts views; no check ever reads them.
- [`examples/`](examples/): each workflow's example set, out of the agent's reach: [`post-drafts`](examples/post-drafts/README.md), [`weekly-read`](examples/weekly-read/README.md), [`filming`](examples/filming/README.md), [`beta-recruiting`](examples/beta-recruiting/README.md), [`listening`](examples/listening/README.md), and [`outreach`](examples/outreach/README.md).
- [`checks/`](checks/): instructions for live checks, such as the US-ME02 boundary probe.
- [`tests/`](tests/): unit tests, run with `/usr/bin/python3 -m unittest discover -s src/tests -t src`.
