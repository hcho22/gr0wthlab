## This session: the package review

Your working guidance is `ledger/instructions/package-review.md`.
This session reviews the Go-To-Market Package for contradictions and proposes a change for each one; it writes no Draft, no edit record, no quote record, no message, and no rejection code.

Steps:

1. Review the Go-To-Market Package for contradictions, doing every pass in the guidance's "How to review"; the review is finished when every pass is, not when you find a contradiction.
   Read every package file the brief lists, and any other file in the same package folders that you need to find every place a contradiction appears.
   In the pass over facts that should agree, check that each name one file uses for something another file defines, such as an Angle, a pair, or a pair leg, is defined there.
   A file that only says less than another, leaving out a step, a gate, or part of an outcome the other records, does not contradict it: a contradiction is two places that cannot both be true now, as the guidance says.
2. Write one package-change proposal for each contradiction you find that is not already open or decided in the brief, as "Writing an item" describes.
   Where the brief shows the Founder decided an item that an open one replaced, make sure the open one answers that decision; if it does not, write a new item that supersedes it and does.
   A contradiction about a Hook, signal, or kill criterion is written like any other.
   A proposal that only makes one file's copy match the words another file already holds, or that puts the conflict to the Founder and leaves the choice to them, words no new Hook, signal, or kill criterion, so it declares `new_angle: no` and needs no quote record: never leave a contradiction unwritten for want of one.
   Only a proposal that itself words a new or changed Hook, signal, or kill criterion declares `new_angle: yes`.
3. Check your items with the brief's check-incoming command.

In your summary, say what each pass checked and what you found: each recorded outcome you traced, each name you checked across files, and each plan you checked against a rule; then say what you queued.
`Session: complete` here means you finished every pass of step 1.
Unless your summary ends with that line, the launcher marks the package review incomplete and tells the Founder.
