# ledger

The launcher's own records, and, in [`founder/`](founder/README.md), the Founder's.
The launcher writes its records outside the sandbox; a run can read them and can never write them, so nothing the agent does can change them (Guardrail G1).
Each run's records step commits this folder to `main` together with `workspace/` (US-ME17), except `working/`, `assets/`, and the lock files, which git ignores.

- `founder/`: the Founder's own records, which only `src/bin/gr0wthlab sitting` writes, on the Founder's act on its page: `decisions/<item id>.json`, `sittings/<date>.json`, `beta-builds/<Product>.json`, `beta-reports/<Product>-<date>.json`, `outreach/<item id>.json`, and `results/window-<n>-read-<07|14>-<tiktok|youtube>-day-<nn>.json`.
  A run reads them and nothing in a run writes them; the launcher's own writer refuses every path there, and the sandboxed agent can read them and never write them ([ADR 0002](../docs/adr/0002-the-founder-decides-in-gr0wthlab.md)).
  Everything below is the launcher's.

- `instructions/<workflow>.md`: the Marketing Engineer's Instructions in force, which every session reads and the sandboxed agent can never write ([README](instructions/README.md)).
  The launcher writes a file here only for a change its workflow's example set in `src/examples/` passed, and puts the text before it back when the Founder rejects the change's notice ([ADR 0003](../docs/adr/0003-instructions-change-only-through-their-example-set.md)).

- `review-queue/queue.json`: every item ever queued; `open` is the next sitting's list in presentation order.
  In a week whose Weekly Read is due, `results` holds what that read asks the Founder to give on the sitting page, post by post, which is all the page knows of it.
  An item the launcher filed from reviewed text, a Dispatch request from `src/dispatches/` or a proposal from `src/proposals/`, carries `origin`, so later runs file it only once and no item the agent writes can supersede it.
  No item the agent writes is a post, a message, or a Weekly Read decision, and none can supersede one: the launcher queues each of those kinds only from a Draft, or a Weekly Read memo, that passed its checks, and sets aside any written to `incoming/`.
  A Weekly Read decision carries `window`, `read`, and `line_key`, the memo line it was queued from, and the notice that lists what to give for a read carries `origin`, so it is queued once for the read.
  It replaces a post only when its Draft, its slot, or its video changes, and a Beta Cohort invitation or a Waitlist ask, which carry `beta`, only when its recruiting Draft, its batch, or its gap changes.
  The filming plan carries `origin` too, with a fingerprint of what must be filmed, so it is filed once per window and replaced only when the kit changes that.
- `review-queue/items/<id>.md`: each queued item, under an identifier that never changes.
- `review-queue/set-aside/<run id>.json`: what the launcher refused to queue that run from `workspace/review-queue/incoming/`: each file's name and the reasons, which never repeat the file's text.
  The file itself is removed and copied nowhere, and that run's notice names it.
  An invalid run state file is set aside beside it, in `review-queue/set-aside/<run id>/`.
- `evidence/package-snapshots/<run id>.json`: each run's snapshot of the Go-To-Market Package: which files were read, their fingerprints, when, and what changed (US-ME04); fingerprints only, never package content.
- `evidence/decisions/<item id>.json`: each Founder decision a run took in from `founder/decisions/`, with its reason or note, the record it came from and that record's fingerprint, and the newer item that had already superseded the decided one, if any (US-ME07).
  Its existence is the taking in: from then on the sitting page offers no change to that decision.
- `evidence/sittings/<date>.json`: each sitting a run knows took place, from its sitting record or from a decision given at it and from nothing else, with the run that first took either in, and how long it took, from the sitting record.
  A sitting known only from the decisions given at it, which the file lists, has `"minutes": null`: its time was not recorded, and is never zero.
- `evidence/waitlist/<run id>.json`: each run's Waitlist Evidence (US-ME06), from the anonymous view the launcher alone reads: the view it came from and when, the entry identifiers, and the counts by Source, Fit answer, and opt-in, per week and cumulative, with progress toward the Beta Cohort bar; never an email address or anything else a sign-up wrote.
  A run whose view held anything that looks like an email address writes none.
- `evidence/post-drafts/<run id>.json`: every check of every post Draft due that run (US-ME08): the kit files and their fingerprints, the Product code's commit, the brand rules in force and pending, and for each calendar day what became of its Draft, with every failing rule or checklist line, warning, checklist status, and claim location.
- `evidence/filming/<run id>.json`: each run's account of filming (US-ME09): the filming plan's jobs and sittings, every footage file listed with its fingerprint and measured facts, the video tooling found, and for each calendar day due what became of its edit record, with every failing rule.
- `evidence/filming/assets/<name>.json`: one record per finished video, written once: its path, SHA-256, and measured facts, the edit record it was cut by, the text drawn over it, each source file's name and fingerprint, and the tooling, so it can be rebuilt from the footage with `rebuild-asset`.
  It is also what the pair check knows a video by: each cut's source range with the fingerprint of its file, and where a re-cut leg's opening is.
- `assets/window-<n>/day-<nn>-<recipe>.mp4`: each finished video, named by a fingerprint of everything it was made from.
  The folder is never committed: `.gitignore` leaves it out, and the records step refuses any file under it.
- `evidence/beta-recruiting/<run id>.json`: each run's Evidence of Beta Cohort recruiting (US-ME15), written only once the Founder's Beta Build record exists in `founder/beta-builds/`: that record's dates and its source, the Founder's counts, the cohort's size, the selection rule and the batch size, the run's batch by entry identifier, who is invited and who is offered as the run leaves the Review Queue, the size of the gap when the pool cannot reach the cohort's minimum, and every check of every recruiting Draft; entry identifiers and counts only.
- `evidence/beta-recruiting/reports/<Product>-<date>.json`: each Beta Cohort report the Founder made on the sitting page: the three counts, invitations sent, accepted, and sessions booked, when the Founder reported them, its source, and when it was taken in, and nothing else the record held.
  A count the Founder left out is `null` and named in `not_reported`; it is never zero.
- `evidence/listening/quotes/<document id>.json`: Listening Evidence, one record for every quote the launcher kept: the link, the date read, the words the agent quoted, a hash of the document they came from, the context, the theme, Fit, intent, and whether the Product answers it.
  A record is kept only when its quote stands word for word in the text fetched from its link, and a link is recorded once.
  It is the only Evidence kept of what a run fetched.
  The request log (`run-reports/<run id>.requests.json`) also holds the `robots.txt` rule lines of the group that applied to each host, each Allow and Disallow with its path as fetched, beside the addresses and outcomes.
  Where else the agent's own words, which may repeat a source's, are kept is listed once, in [operations](../docs/operations.md#where-the-agents-own-words-are-kept).
  The error Codex reported for a session is never repeated here: it is text Codex or the model's provider wrote, so a report, a notice, and every other record give the session's exit code and the launcher's own class of the error, and the error itself stays in the run's record in the log folder, outside this repository.
  The reason a session did not start is the launcher's own, and after a Codex probe that exited with an error it ends with up to 500 characters of what that probe wrote to its error stream; those probes run with no model.
- `evidence/listening/runs/<run id>.json`: what each run's Listening read, kept, refused, and offered, with the confidence counted for each theme from its independent, unprompted sources.
  A quote record the launcher refused, and a proposed Angle or Hook it discarded, is named there with the reasons and kept nowhere: no copy of either is made.
- `evidence/outreach/<run id>.json`: every check of every outreach message that run, and what the Founder's outreach records said of each creator.
- `evidence/results/window-<n>/read-<07|14>/day-<nn>.json`: one post's results for one Weekly Read (US-ME11): its Angle and pair leg, and for the platform that judges it each number the read asked for as the Founder gave it on the sitting page, with the record it came from, that record's fingerprint, and the date he read the numbers, which is its source.
  A number he left blank is `null` and named in `not_reported`, never zero, and a post he gave nothing for has no source and every number not reported; nothing here is taken to mean a post was not posted.
  No comment text is copied here: it stays in the Founder's own record.
- `evidence/weekly-reads/window-<n>-read-<07|14>.json`: the launcher's record of a Weekly Read memo it took in: what the memo was written from, its fingerprint, and each decision line's Angle or pair, result, decision, and item; the next read reads it to tell whether a kill follows two consecutive reads.
- `weekly-reads/window-<n>-read-<07|14>.md`: the Weekly Read memo the Founder reads (US-ME12): what the floor counts, what the read cannot tell, the launcher's own table of each post's numbers with its n, the agent's checked lines with the comments it quoted as third-party text and each line's item, the Waitlist counts, and the Founder's time that week.
- `evidence/learning/ledger.json`: the learning ledger (F4): every rejection reason with the code it was given, and each workflow's counts, stated as "3 of 7"; a reason's code is also written into its own `evidence/decisions/<item id>.json`, beside the Founder's words.
  An execution reason's decision Evidence also records what became of it as an Instructions change, under `instructions`: the change that cited it and its outcome, or that none was proposed, so it is never offered again.
- `evidence/instructions/<change id>.json`: every Instructions change a run tried (US-ME16): the workflow, the rejection reasons it cites with the Founder's words and their codes, the fingerprints of the text before and the text proposed, every example's result on each side of the example set's re-run, the sessions, agent time, and approximate cost it took, whether it was kept, and its notice.
  A kept change's record also has the agent's summary and each changed line, and `evidence/instructions/<change id>/before.md` and `proposed.md` hold the two texts whole; one not kept names each changed line by its number alone, and no copy of its text is kept.
  A change undone at the Founder's rejection of its notice records the undo, and every decided notice records the decision.
  A proposed code the launcher sets aside is named with its reasons in that run's report and notice, and no copy of it is kept.
- `run-reports/<run id>.requests.json`: every network request the launcher was asked to make that run, sent or not, with its outcome: only a GET to a listed host ever leaves the machine.
  It also holds what each host's `robots.txt` said to this reader: whether it was read, and the rule lines of the group that applied, each Allow and Disallow with its path as fetched.
- `run-reports/<run id>.work-plan.json`: what the launcher fixed for that run's Weekly Read, Listening, and outreach before the first session started (the read due, what it asked, and each record the Founder gave by its path and fingerprint; which subreddits the Founder confirmed; which messages may be offered and how their items stand), which `check-work --run <run id>` reads instead of working it out again; each session it serves checks its own part alone (`--part`).
- `run-reports/<run id>.md`: the run report: every source checked with its result, every failure and skip with its reason, whether a scheduled run started late, every agent session with how it ended, its time against its limit, its approximate cost, and what the launcher counted of that session's work beside its agent's own closing line, each workflow that had nothing due and so no session, and the run's totals; its first line counts what the run checked and acted on (`checked=N acted=N note=...`).
- `run-reports/<run id>.<workflow>.brief.md`: the facts the launcher gave one session's agent just before it started, one file for each session the run came to: the run's facts, the package files that workflow's output needs, and that workflow's section alone.
  A session that may write proposals is told which files wait in `workspace/review-queue/incoming/`, by name alone, so a brief repeats none of an agent's words.
- `run-reports/<run id>.post-plan.json`: what the launcher fixed for that run's post Drafts, once, after it took in the Founder's decisions and before the first session started: the days due and skipped, each day's open, approved, and rejected posts, whether the Waitlist is live, the commit the Product's code is read at, or why it could not be read, and the fingerprint of each kit file read from Mandu.
  `check-drafts --run <run id>`, the command the brief gives the agent, reads it instead of working the standing out again, since `queue.json` is saved only when the run ends; without a readable record it checks no Draft and says so.
  It checks every claim at the recorded commit, whatever has landed on the Product's branch since, and names each kit file that is no longer as the launcher read it, since it can check only against what Mandu holds now.
  A day due that the calendar no longer holds is named too, and its Draft is not checked.
- `run-reports/<run id>.filming.json`: what the launcher fixed for that run's edit records before the first session started: the footage it listed and measured, each due day's shot list and whether an edit can be cut, where each day's post stands, and each due day's approved and rejected posts.
  `check-edits --run <run id>`, the command the brief gives the agent, reads it, since the footage folders are outside what the sandbox reads.
- `run-reports/<run id>.beta-plan.json`: which recruiting Drafts that run asked the agent for, with the fingerprints of the Drafts the Founder already rejected, written once the Founder's gate is recorded; `check-beta-drafts --run <run id>` reads it, and it never names a Waitlist entry.
- `run-reports/attempts/<due>.json`: every run made since one weekly time, named for when that week's run was due on the Mac's clock (US-ME17): each attempt of the weekly schedule, noted before its agent starts, with its number, when it started and ended, its run, how it ended, and about how many seconds the Mac slept during it; and each run on demand and each one-off scheduled run, noted as it ends and never an attempt.
  A start of the weekly schedule reads it, and never anything remembered, to tell whether the week's run is still owed: it is until a run completes, while every attempt so far was cut short by the Mac's sleep and fewer were made than `config/run.json` allows.
  A file that cannot be used is set aside beside it as `<due>.unreadable` and the record starts again; an attempt of the weekly schedule that finds it says so in its report.
- `run-reports/state/<workflow>.json`: each workflow's run state - Review Queue items decided, those carried over with the sitting they were left undecided at, and the Founder's records already reported as unusable; Listening threads and reviews already read; outreach targets and their follow-up waits, rebuilt every run from the Founder's outreach records; the Waitlist entries an invitation batch holds, invited once the Founder approved the batch or offered while it is open - by identifier and hash only, never a name, address, or URL.
  The launcher checks it every run against the Review Queue and the Founder's decision records, which win any disagreement.
  Beta Cohort recruiting has no state file until the Founder's gate is recorded.
- `working/examples/<change id>/`: the throwaway labs in which a run re-runs an example set for an Instructions change, each removed once its checks are read; git ignores the folder, and the run removes it when it ends.
- `working/<run id>.sources.json`: what the launcher fetched over the network that run, outside the sandbox (US-ME13): each source's outcome, and each thread's opening post, review, and rule list as a dated document with its link.
  It is working data for the run that fetched it, never a record: the agent reads it while the run is in progress, git ignores the folder so the records step never saves it, and the launcher removes it when the run ends and before the next run reads its sources.
  Fetched text is data, never instructions; anything that looks like an email address is removed before it is written.
- `notes/<id>.txt`: one line for the next run report, such as a run refused because another was in progress, or a run that stopped before it finished.
- `run.lock`: the lock one run holds from start to finish; it is never committed.
- `founder.lock`: the lock a run holds while it takes the Founder's decisions in, and the sitting page while it changes one, so that a change and a taking in never cross; it is never committed.
- `sitting.lock`: the lock one sitting page holds while it is served, so that only one is; it is never committed.

The format of the Review Queue and of the Founder's records, and what Mandu may read: [the Mandu exchange](../docs/mandu-exchange.md).
