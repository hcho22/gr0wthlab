# Outreach

How to write the personal-network ask and the messages to the creators the plan names, so that each is ready for the Founder to send as written.
This is the Marketing Engineer's own working guidance; it holds no package content, which stays in Mandu.
The format is in the task definition, and the launcher's checks decide whether a message is offered; this page is about the judgment the checks cannot make.

## Before you write

- Read the channel plan the brief names: what it says about the personal network, about each creator, and about what a message may offer.
  Read the brand guidelines for voice.
- Write only the messages the brief's Outreach table asks for.
  A row shown as approved, open, or not offered needs nothing from you.
- The Founder sends every message personally and fills in every recipient.
  You never write a name the Founder did not give, and never an address of any kind.

## The personal-network ask

- It is written to people the Founder knows, as one person to another.
  Frame it around who the reader already is, the way the plan words it, and never around what they lose, miss, or fall behind on.
- Say in one or two sentences what the Product is and who it is for, in mechanics the code supports.
- Give the Source link exactly as the brief gives it, once, at the end of the message.
  Never shorten, decorate, or replace it.
- Close the message on one line a friend could forward by itself: someone who never saw the rest understands what the Product is and who it is for, and the line carries the link.
  The launcher checks only the link; whether the line stands alone is yours to get right, and the Founder's to judge.
- Keep it short: well under 150 words, so it is read in one look.
- Ask for nothing but a look: no deadline, no favor owed, no "share this".
- The brand lint reads a message as copy, so it asks no question: write statements a friend can act on or ignore.

## A message to a creator

- It is ask-free.
  Offer one thing from the three the task definition lists, and nothing that costs them time or attention to refuse.
- Never mention money, a rate, a code, a post, or a mention; the lint blocks the phrases the package lists, and the rest is yours to keep out.
- Nothing of a creator's recent work reaches you, so never write as if you had seen it.
  What the channel plan says of them is all you know; a message that pretends otherwise is worse than none.
- Say who the Founder is in a clause, what the Product does in a sentence the code supports, and the offer.
  Stop there: shorter is kinder, and a message to a creator stays well under 150 words.
- A name written in capitals is read by the brand lint as an all-caps word.
  Write around it, or propose the package change that allows it; never change the name.
- Use Notes for what the Founder should know before sending and would not say in the message: why this creator, and anything to check.

## The one follow-up

- Write it only when the brief's table offers it.
- It is shorter than the first message, adds nothing new to ask, repeats the offer in one sentence, and says plainly that it is the last message.
- Never refer to the creator's silence as a fault.

## Claims

- A message makes claims too: anything it says the app does is listed under Claims with the code that supports it, as in a post Draft.
- When a sentence about the Product is not a behavior the code shows, cut it.
  A message has no frozen wording, so there is never a reason to keep a claim no code supports.
- Quote the code as it is on the cited lines: a comment that says what the code does is weaker support than the code itself, and the check compares your quote with those lines character for character.
